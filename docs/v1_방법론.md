# OIBC v1 설명서 — 태양광 집합자원 구성·하루전 예측

v1 방법의 "무엇을, 왜, 어떻게"를 설명한 문서. 대회 규정·채점·제출 규격은 `대회_규정.md`, 실행 방법은 루트 `README.md`, 제출 이력은 `EXPERIMENTS.md`.

---

## 핵심 요약

- **문제**: 태양광 발전소 253곳을 두 묶음(G1, G2)으로 나누고, 각 묶음의 1시간 발전량을 하루 전에 맞힌다. 틀린 만큼 `SMP × 가중치 k × |오차|`로 벌금(페널티)을 낸다.
- **v1 전략 (가장 대중적·안정적인 2단계)**
  1. **예측**: 발전소마다 "설비이용률(발전량 ÷ 설비용량)"을 기상 예보 + 태양 위치로 맞히는 **LightGBM** 모델을 만들고, 묶음별로 더한다.
  2. **구성**: 예측을 고정한 상태에서, 과거 1년 검증 오차가 묶음 안에서 **서로 상쇄**되도록 발전소를 G1/G2에 배정한다(지역 탐색 최적화).
- **안정성 장치**: 시간 순서 검증(과거로 학습 → 다음 1년으로 시험), 예보 결측은 버리지 않고 대체, 누수 금지 규칙을 코드에 assert로 박음, 제출 전 형식 검증 스크립트.
- **핵심 통찰**: 두 묶음 오차의 절댓값 합은 "전체 오차의 절댓값"보다 작아질 수 없다. 그래서 **점수의 대부분은 예측 정확도가 결정**하고, 구성은 두 묶음의 오차 방향을 맞춰 "새는 벌금"을 줄이는 역할이다.

## 1. 전체 흐름

```
[원본 데이터]
  sites.csv · generation · forecast A/B (round 10, 17) · smp
        │
        ▼
① 전처리 ── 예보 결측 대체(버리지 않음) · 발전량 이상치/장애일 제거
        │
        ▼
② 피처 ── 예보값 + 태양 고도/방위 + 청천일사×(1−운량) + 같은 날 ±1시간·일평균 + 달력 + 발전소 정보
        │
        ▼
③ 모델 ── LightGBM(L1 손실) × 2개 (10시 예보용, 17시 예보용) → 평균
        │
        ├─▶ ④ 검증 (2022.6~2024.5 학습 → 2024.6~2025.5 시험) → 발전소별 오차 저장
        │          │
        │          ▼
        │   ⑤ 구성 최적화 (오차가 묶음 안에서 상쇄되게 G1/G2 배정)
        │
        ▼
⑥ 최종 학습 (2023.6~2025.5) → 평가 구간 예측 → 묶음별 합산
        │
        ▼
⑦ 형식 검증 → submissions/v1/composition.csv, forecast.csv
```

## 2. 단계별 설명 — 무엇을, 왜

### ① 전처리

**예보 결측 대체.** 평가 구간 예보에 264행이 비어 있습니다. 그 시각도 채점되므로 버리면 안 됩니다. 아래 순서로 채웁니다.

1. 같은 지점·같은 시각의 **다른 라운드** 예보 (10시 ↔ 17시)
2. 같은 날 안에서 앞뒤 시각으로 **선형 보간**
3. 같은 시각 **다른 지점들의 중앙값**
4. 강수류는 0

> ⚠️ 왜 "같은 날 안에서"인가? 시각은 우측닫힘이라 `ts=00:00`은 전날 23~24시입니다. 대상일 경계를 넘어 다음 날 01시 값을 끌어오면, 그 값은 **더 늦게 발행된 예보**라 예측시점(전날 17시) 이후 정보가 섞입니다(누수). 그래서 `대상일 = (ts − 1시간)의 날짜`로 묶어서만 보간·이동합니다.

**발전량 정제.** 음수, 용량의 120% 초과, 해가 떠 있는데 하루 종일 0인 날(장애)은 **학습에서만** 뺍니다. 채점용 검증에서는 그대로 둡니다. 실제 평가 실적에도 장애·출력제어가 표시 없이 섞여 있기 때문에, 검증 점수가 실전과 비슷하게 나오게 하려는 것입니다.

### ② 피처

| 묶음 | 예시 | 왜 넣나 |
|---|---|---|
| 기상 예보 A·B | 운량, 기온, 습도, 자외선지수, 시정, 운고, 강수 | 구름·비가 발전량을 결정 |
| 태양 기하 | 고도, 방위, cos(천정각) | 해가 얼마나 높은지 = 일사의 상한 |
| 청천일사 × (1 − 운량) | 물리적 직관을 한 변수로 | 트리 모델이 곱셈 관계를 배우기 어려워서 미리 만들어 줌 |
| 같은 날 ±1시간, 일평균 운량 | 구름 시점이 1시간 어긋나는 예보 오차 완화 | 같은 대상일 안에서만 계산 |
| 달력 | 시, 연중일(sin/cos), 월 | 계절·시간 패턴 |
| 발전소 | site_id, 용량, 위경도, 관측지점 거리 | 발전소별 효율·방향 차이 |

**쓰지 않는 것**: SMP(당일 SMP 사용 금지 규칙), 실측 기상(평가 구간에 없음), 과거 발전량 시차값(마지막 7시간 규칙 위험 + v1 단순화).

### ③ 모델 — 왜 LightGBM, 왜 L1

- **LightGBM**: 표 형태 데이터에서 가장 널리 쓰이고, 결측·범주형에 강하며 빠릅니다. 주최 측 baseline도 같은 계열입니다.
- **타깃 = 설비이용률(0~1)**: 14 kW짜리와 1,387 kW짜리 발전소를 같은 눈금으로 학습하기 위해. 예측 후 용량을 곱해 kWh로 되돌립니다.
- **L1 손실(절대오차)**: 벌금이 `|오차|`에 비례하므로, 평균이 아니라 **중앙값**을 맞히는 L1이 이론적으로 맞습니다. 출력제어처럼 가끔 튀는 값에도 덜 흔들립니다.
- **가중치 = 용량 × k**: kWh 오차가 큰 대형 발전소와 한낮(k=3)을 더 신경 쓰게 합니다.
- **라운드 10 / 17 모델 평균**: 두 예보를 각각 쓴 모델을 평균하면 한쪽 예보가 빗나갔을 때의 위험이 줄어듭니다(앙상블). v6부터는 50:50 대신 **10시 0.3 · 17시 0.7**로 가중합니다(대상일에 가까운 17시 예보가 더 정확함, 근거는 `EXPERIMENTS.md` v6).
- **야간 0 고정**: 해가 없으면 발전량은 0. 모델이 엉뚱한 작은 값을 내는 것을 막습니다.

### ④ 검증 — 미래를 흉내 내기

| 구간 | 기간 | 역할 |
|---|---|---|
| 학습 | 2022.6 ~ 2024.5 (2년) | 모델 학습 |
| 조기 종료 | 학습 구간의 마지막 60일 | 트리 개수 결정 |
| 시험(검증) | 2024.6 ~ 2025.5 (1년) | 점수 측정, 구성 최적화 재료 |

실제 대회가 "과거 → 다음 1년"이므로 똑같이 **시간 순서로** 나눕니다. 무작위로 섞으면 같은 날의 이웃 시각이 학습·시험에 동시에 들어가 점수가 부풀려집니다. 시험 연도는 트리 개수 결정에도 쓰지 않아 점수가 낙관적으로 나오지 않게 했습니다.

평가 지표는 MAE가 아니라 **대회 식 그대로의 S와 W**입니다(검증 연도 SMP, k 사용).

### ⑤ 구성 최적화 — 오차 상쇄 (OR 파트)

**아이디어.** 발전소 A가 +10 kWh, B가 −10 kWh 틀렸다면, 같은 묶음일 때 오차 0, 다른 묶음일 때 오차 20입니다.

**수식.** 발전소 i, 시각 t의 검증 오차 `R[i,t]`, 시각 가중치 `w[t] = 0.10·SMP·k`라 하면

```
최소화  W = Σ_t w[t] · ( |Σ_{i∈G1} R[i,t]| + |Σ_{i∈G2} R[i,t]| )
제약    cap(G1) ≥ 20,000 kW,  cap(G2) ≥ 20,000 kW
```

**하한(가장 중요한 통찰).** 삼각부등식 `|a| + |b| ≥ |a + b|` 때문에

```
W ≥ W_LB = Σ_t w[t] · |전체 오차(t)|
```

전체 오차는 구성과 무관합니다. 즉 **어떻게 나눠도 W_LB 밑으로는 못 내려갑니다.** 구성이 할 수 있는 일은 "매 시각 두 묶음 오차의 부호를 같게 만들어" W를 W_LB에 붙이는 것뿐입니다. 그래서:
- 예측을 잘하는 것이 1순위(W_LB 자체를 낮춤)
- 구성은 2순위(W와 W_LB의 격차를 줄임)
- "좋은 발전소만 한 묶음에" 전략이 의미 없는 이유도 여기서 나옵니다.

**알고리즘: 지역 탐색(Local Search).** 정수계획(MIP)으로도 풀 수 있지만 8,760시간 × 절댓값이라 변수가 많습니다. 가장 대중적이고 안정적인 휴리스틱을 씁니다.
1. 시작 구성(참조 구성 + 무작위 19개)에서 출발
2. **1-이동**: 발전소 하나를 반대편으로 옮겨 W가 줄면 채택
3. **2-교환**: 양쪽에서 하나씩 맞바꿔 W가 줄면 채택(용량 제약 때문에 1-이동이 막힐 때 유용)
4. 더 이상 개선이 없으면 멈춤, 20개 출발점 중 최선 채택

**과적합 점검.** 검증 1년의 오차에 너무 딱 맞춘 구성은 내년에 통하지 않을 수 있습니다. 그래서 홀수 주로 최적화 → 짝수 주에서 채점해 개선이 유지되는지 확인합니다. 유지될 때만 최적 구성을 쓰고, 아니면 참조 구성을 유지합니다.

**규칙 준수.** 구성은 학습 구간(검증 연도)의 오차·SMP로만 정합니다. 평가 구간 예보·SMP로 그룹을 나누는 것은 금지입니다.

### ⑥ 최종 학습과 예측

최근 2년(2023.6~2025.5)으로 같은 설정의 모델을 다시 학습(트리 개수는 ④에서 찾은 값)하고, 평가 구간 예보로 예측 → 라운드 평균 → 야간 0 → 묶음별 합산합니다.

### ⑦ 제출 전 형식 검증

형식 오류도 제출 횟수(일 3회, 총 20회)를 깎으므로 반드시 통과시킵니다.

- [ ] composition: 253개소 중복·누락 없음, G1·G2 각각 20,000 kW 이상
- [ ] forecast: 17,520행, 묶음별 8,760시각이 smp.csv와 일치
- [ ] 음수·빈 값·무한대 없음, 시각에 `+09:00`

## 용어집

| 용어 | 뜻 |
|---|---|
| 집합자원(VPP) | 작은 발전소들을 묶어 하나처럼 전력시장에 참여하는 단위 |
| SMP | 계통한계가격, 그 시각 전기 1 kWh의 가격(원) |
| 설비이용률(CF) | 발전량 ÷ 설비용량. 0~1 사이 |
| 우측닫힘 | `ts=13:00`은 12:00~13:00의 양 |
| 라운드 10 / 17 | 대상일 전날 10시 / 17시에 발행된 예보 |
| 누수(leakage) | 예측 시점에는 알 수 없는 정보가 모델에 들어가 검증 점수가 부풀려지는 것 |
| L1 손실 | 절대오차를 줄이는 학습 기준. 중앙값을 맞힘 |
| 조기 종료 | 검증 오차가 더 안 줄면 트리 추가를 멈추는 것(과적합 방지) |
| 지역 탐색 | 현재 해에서 작은 변화(이동·교환)를 반복해 개선하는 최적화 방법 |
